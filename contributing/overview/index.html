How to contribute

Thank you for helping. This page tells you what a change needs before it can merge. Every rule here is enforced by CI, so a green pull request is a mergeable one.

Before you start

Section titled “Before you start”
  • Small fixes (typos, bugs, docs): open a pull request directly.
  • A new component, or adding, renaming, or removing a token: open an RFC first. CI rejects such changes when they do not reference an accepted RFC.
  • A new theme: use the “New theme” issue form. Themes of real brands are only accepted with the brand owner’s consent, because everything in this repository is public.

Commits and pull requests

Section titled “Commits and pull requests”
  1. Sign off every commit. Use git commit -s. The sign-off line certifies the Developer Certificate of Origin: you wrote the change or have the right to submit it under the project license. There is no separate contributor agreement.
  2. Use Conventional Commits for commit messages and the pull request title, for example feat(tokens): add focus ring tokens or fix(web): restore dialog focus on close. Pull requests are squash-merged, so the title becomes the commit on main.
  3. Keep generated files generated. Never edit a file marked GENERATED. Change its source and regenerate; CI compares the two.
  4. Do not record snapshot baselines locally. Visual baselines are recorded in CI so that no one’s machine influences them.

What CI checks

Section titled “What CI checks”
Check What fails it
Lint and format pnpm lint reports anything
Unit tests pnpm test fails
License gate A dependency with a license outside the allowlist
Asset licenses A font or brand asset missing from licenses/assets.yml
Sign-off and title A commit without Signed-off-by, or a non-conventional pull request title
Secret scan A credential in the diff or history
Vulnerability scan A dependency with a known vulnerability
Workflow lint An unsafe or invalid GitHub Actions workflow

Two more checks cover the token source: pnpm tokens:lint fails on an invalid token, a broken reference, or a tier violation, and pnpm tokens:contrast fails when any declared color pair misses its contrast requirement in any color mode. See docs/contributing/add-a-token.md.

More checks join as the platform packages land.

Dependencies

Section titled “Dependencies”

Every dependency, font, and icon must be free or open source under an OSI-approved license on the allowlist. Fonts must be OFL-1.1. If you believe an exception is justified, say why in the pull request; exceptions are individual, dated, and recorded in licenses/curations.yml.

Versions are pinned exactly, and versions published less than seven days ago are refused.

Borrowing from other design systems

Section titled “Borrowing from other design systems”

Compare against the systems in docs/research/prior-art.md, and borrow behaviour and naming conventions freely. Copy code, tokens, or assets only when the source license is on the allowlist, and add the attribution to NOTICE. Never copy brand assets.

License of your contribution

Section titled “License of your contribution”

By contributing you agree that your contribution is licensed under Apache-2.0, the license of this project.
