3.6

Dialog

Interrupts a task to ask for something or to confirm it, in a panel above the screen.

Spec version 1.0.0, proposed in RFC 0006. The DialogSize and SheetEdge types used by every platform’s implementation are generated from this spec.

Implemented in React (Dialog, AlertDialog, and Sheet in @raincoat-ui/react), SwiftUI (.raincoatDialog(isPresented:), .raincoatAlertDialog(_:isPresented:), and .raincoatSheet(isPresented:) in Raincoat), and Compose (RaincoatDialog, RaincoatAlertDialog, and RaincoatSheet in io.github.raincoat-ui:ui). The parity matrix shows every component on every platform.

About the renditions

The panels on this page are static renditions, not the component: a small window, with the scrim filling it and a dialog on it. They are styled only with the custom properties of the generated theme stylesheet, and each panel under “In every color mode” selects its mode with a data-theme attribute. A real dialog covers the whole window, and on iOS dialogs and sheets are the system sheet and an alert dialog the system alert.

Properties

Section titled “Properties”

Dialog

Section titled “Dialog”

A panel centered over the screen, for a short task that must be finished or abandoned before going on: rename, choose, fill in a few fields.

Property Values Default Description
size sm, md, lg md The width of the dialog. On a window narrower than that, it spans the width of the window less a margin.

Size

Section titled “Size”
Value Use
sm A dialog with a sentence or two and a few buttons.
md The default width, for a short form.
lg A dialog with wide content, such as a table or a preview.

AlertDialog

Section titled “AlertDialog”

A small centered dialog that asks people to confirm something consequential or irreversible. On iOS it is the system alert.

Property Values Default Description
destructive true, false false The confirming action destroys something, such as deleting. Its button is a danger button on the web and on Android, and has the destructive role in the iOS alert.

Sheet

Section titled “Sheet”

A panel that rises from the bottom edge or slides in from the end edge, for a longer task or one that keeps the screen behind in view.

Property Values Default Description
edge bottom, end bottom The edge of the window the sheet comes from. On iOS every sheet is the system sheet, from the bottom on iPhone and centered on iPad.

Edge

Section titled “Edge”
Value Use
bottom Rises from the bottom edge. It is as wide as the window, up to the medium panel width, and centered on wider windows.
end Slides in from the end edge: the right in left-to-right layouts, the left in right-to-left ones. On a window less than twice its width, it comes from the bottom instead.

Content

Section titled “Content”
Content Description Required
Title Names the dialog, and is what assistive technology reads first. In an alert dialog it says what will happen, as a question: “Delete this address?”. It wraps and is never cut short. Yes
Description One sentence under the title that the dialog is described by: what the task is for, or what confirming does. No
Body Any content: text, fields, a list. It scrolls between the header and the footer when it does not fit. No
Action label The label of the primary action, the last button of the footer. In an alert dialog it repeats the verb of the title: “Delete address”. In an alert dialog
Cancel label The label of the button that closes the dialog without doing anything, such as “Cancel”. It is the alert dialog’s least destructive action, and where focus starts there. In an alert dialog, and in a dialog or sheet without a close button
Close label The name of the close button, read by assistive technology, such as “Close”. The button shows a cross drawn by the component. In a dialog or sheet whose footer has no Cancel

States

Section titled “States”
State Description
Open The dialog is shown and holds focus. The screen behind is under the scrim and inert.
Scrolled The body has content scrolled beneath the header or above the footer. A hairline shows at that edge.
Short window The window is too short to show the header, the footer, and three lines of the body, as at 400% zoom. The whole container scrolls as one, and the header and footer scroll with it.
Stacked The footer’s buttons do not fit in a row, as with long translated labels. They stack, the primary action first.
Dragging A bottom sheet on iOS or Android follows a finger that drags it down. Let go far enough or fast enough, it closes; otherwise it settles back.

Accessibility

Section titled “Accessibility”
Requirement Detail
Role A modal dialog, or an alert dialog for an alert dialog, named by its title and described by its description. On iOS an alert dialog is the system alert.
Name The title. The close button is named by the app.
Focus On open, focus moves into the dialog: to the title by default, so that a screen reader starts at the top and nothing is activated by accident. The app can name another target, such as the first field of a form. In an alert dialog focus starts on the least destructive action, the Cancel button. On close, focus returns to the control that opened the dialog; if that control is gone, to a target the app names. The title takes focus but shows no ring: it is not a control.
Hidden While a dialog is open, everything behind it is hidden from assistive technology and cannot be reached with the keyboard or a pointer.
Dismissal A dialog and a sheet close on Escape, a click or tap on the scrim, the close button or Cancel, and the system’s back gesture on Android; a bottom sheet also closes when it is dragged down on iOS and Android. An alert dialog closes only on Escape, Cancel, the back gesture, and its own actions: Escape and back mean Cancel, and the scrim does nothing, so that a stray tap never counts as an answer. Every way out but dragging works without a pointer, and dragging is never the only one.
Text size The title, description, body, and buttons grow with the person’s text size setting. At 400% zoom on the web, the largest accessibility text size on iOS, and a font scale of 2 on Android, the dialog can still be read and used to the end.
Contrast The title and description have 4.5:1 against the container, and 7:1 in the high-contrast modes. The drag handle has 3:1. The scrim is not a background for contrast, because what is under it is unknown.

Keyboard

Section titled “Keyboard”
Keys Action
Tab or Shift+Tab Move focus among the dialog’s controls. Focus stays inside the dialog while it is open, and wraps from the last control to the first.
Escape Closes a dialog or a sheet, and cancels an alert dialog. The app can refuse, as while there are unsaved changes.
Enter or Space Activate the focused button, as they do anywhere.

Internationalization

Section titled “Internationalization”
Concern Behavior
Right to left The footer’s buttons and the close button sit at the end edge, which is the left; the end sheet comes from the left. Nothing is placed by left or right.
Long text Titles and descriptions wrap. The footer’s buttons stack when their labels do not fit in a row, as translations up to three times as long as English can.
Scripts The title and description use the heading-md and body-md styles, whose line heights clear stacked Vietnamese diacritics. Chinese, Japanese, and Korean use system fonts.

Motion

Section titled “Motion”
Concern Behavior
Enter The scrim and a dialog fade in, with dialog.enter.duration and its easing. A sheet slides in from its edge while the scrim fades in.
Exit The scrim and a dialog fade out, with dialog.exit.duration and its easing. A sheet slides back to its edge.
Reduced motion Everything fades and nothing moves.

Guidelines

Section titled “Guidelines”

When to use

Section titled “When to use”

Use a dialog for a task that must be finished or abandoned before going on: renaming a file, choosing one of a few options, filling in a few fields. While it is open, the screen behind is covered and cannot be used.

  • If people need the screen behind to do the task, use a sheet, or put the task in the page.
  • Do not use a dialog for a message that needs no decision. A toast or an inline message interrupts less.
  • To show a toast from a dialog or sheet, see the Toast guidelines, With a dialog or sheet.
  • Do not open a dialog from a dialog. Replace the content, or close the first.

Choosing a kind

Section titled “Choosing a kind”
Kind Use it for Avoid
Dialog A short task: rename, choose, fill in a few fields Long forms, or tasks that need the screen
Alert dialog Confirming something consequential or irreversible, such as delete Questions that are not about a consequence
Sheet A longer task, or one that keeps the screen behind in view A confirmation: use an alert dialog for that

Choose a dialog’s size for its content: sm for a sentence or two and a few buttons, md for a short form, lg for wide content such as a table. A sheet comes from the bottom unless it holds something people compare with the screen, such as filters for a list: then from the end edge.

On iOS every dialog and sheet is the system sheet, and an alert dialog is the system alert, which looks like iOS rather than like your theme. That is what people on iOS recognize, and it follows their text size, bold text, and contrast settings.

Writing it

Section titled “Writing it”
  • Give every dialog a title that names it, in sentence case, without a full stop: “Rename file”.
  • In an alert dialog, the title says what will happen, as a question: “Delete this address?”. Its confirming button repeats the verb: “Delete address”, not “Yes” or “OK”.
  • Use the description for one sentence about the task or its consequence. Do not repeat the title.
  • Keep the primary action last in the footer, and put Cancel before it.

Giving a way out

Section titled “Giving a way out”

Every dialog and sheet has one visible way out: a Cancel button in the footer, or a close button at the end of the header. Not both: two buttons that mean the same make people wonder which one keeps their work.

  • Use Cancel when the footer has actions. Use the close button when it has none, as in a dialog that only shows information.
  • Give the close button a name that says what it does, such as “Close”. It shows only a cross.
  • Escape closes every dialog. So does a click or tap on the scrim, except for an alert dialog: there a stray tap must not count as an answer.
  • To keep a dialog open while it holds unsaved changes, refuse to close it and ask first. Every platform lets the app refuse.

Focus

Section titled “Focus”

Focus moves to the title when a dialog opens, so that a screen reader starts at the top and a keyboard user is one Tab from the first control. In a short form, give the first field focus instead. An alert dialog starts on Cancel, never on the destructive action.

When the dialog closes, focus returns to the control that opened it. If that control no longer exists, as after deleting the row it was in, name where focus goes.

Layout

Section titled “Layout”
  • The header and the footer stay in place, and the body scrolls between them. A hairline shows under the header and above the footer while content is beneath them.
  • When the window is too short for the header, the footer, and three lines of the body, as at 400% zoom, the whole dialog scrolls instead.
  • Footer buttons stack when they do not fit in a row, with the primary action on top. Let them: do not shorten a translated label to keep them side by side.

Do and don’t

Section titled “Do and don’t”
Do Don’t
Name the dialog in its title Title it “Are you sure?”
Repeat the verb on an alert dialog’s confirming button Label it “Yes”, “OK”, or “Confirm”
Give one way out: Cancel, or the close button Show the close button beside a Cancel
Let a long title wrap Truncate a title with an ellipsis
Use a sheet when people need the screen behind Open a dialog over a dialog
Close a sheet with a button as well as by dragging Make dragging the only way out
