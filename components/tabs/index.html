3.5

Tabs

Switches between panels of related content in one view.

Spec version 1.0.0, proposed in RFC 0007. The activation mode type used by every platform’s implementation is generated from this spec.

Implemented in React (Tabs, TabsList, TabsTrigger, and TabsContent in @raincoat-ui/react), SwiftUI (RaincoatTabs and RaincoatTab in Raincoat), and Compose (RaincoatTabs and RaincoatTab in io.github.raincoat-ui:ui). The parity matrix shows every component on every platform.

About the renditions

The panels under “In every color mode” are static renditions, not the component: a row of three tabs, the first selected. They are styled only with the custom properties of the generated theme stylesheet, and each panel selects its mode with a data-theme attribute.

Properties

Section titled “Properties”
Property Values Default Description
activation-mode automatic, manual automatic On the web, whether the arrow keys select the tab they move to. On iOS and Android a keyboard moves focus the platform’s way, and Enter or Space selects, as for any control.
keep-mounted true, false false On the web, keeps a panel that is not selected in the page, hidden, so that it keeps its state. Otherwise only the selected tab’s panel is rendered.

Activation mode

Section titled “Activation mode”
Value Use
automatic The arrow keys select the tab they move to. The panel shows at once.
manual The arrow keys only move focus, and Enter or Space selects. For panels that are slow to show.

Content

Section titled “Content”
Content Description Required
Label The text of a tab. One or two words, in sentence case. It stays on one line. Unless an icon is the only content
Leading icon An icon before the label. Decorative when there is a label. No
Accessible name The name read by assistive technology. When there is no label
Panel The content shown while the tab is selected. Yes

States

Section titled “States”
State Description
Rest A tab that is not selected. Its label is muted.
Hover A pointer is over the tab. The label darkens and the tab is filled. Exists only where there is a pointer.
Focus visible The tab has keyboard focus. The focus ring is shown inside its edge.
Pressed The tab is being pressed. It is filled more strongly than on hover.
Selected The tab whose panel is shown. Its label is in the default color, over the indicator.

Accessibility

Section titled “Accessibility”
Requirement Detail
Role tablist. Each tab is a tab, with its selected state and its position, such as “2 of 4”, and the panel is a tabpanel named by its tab. On iOS the row is a tab bar and the selected tab carries the selected trait; on Android the row is a selectable group of tabs.
Name Each tab is named by its label. A tab with only an icon must be given an accessible name. Name the tab list too when a screen has more than one.
Panel focus On the web, a panel with nothing focusable can take focus itself, so its content can be reached. A panel with focusable content is not itself a Tab stop.
Selection Controlled by the app, or left to the component. On the web a click selects a tab when it is pressed.
Focus A ring at least 2px wide with 3:1 contrast against the surface, drawn inside the tab’s edge for keyboard focus. Moving focus to a tab scrolls it into view. On the web and on Android the tab draws it from the focus ring tokens. On iOS the system draws its own focus indicator, which follows the person’s Full Keyboard Access settings.
Target size The area that takes touches is at least 44pt on iOS, 48dp on Android, and 44px on a touch screen on the web, whatever the visible height. A tab’s layout size is its visible size.
Contrast Labels have 4.5:1 against the surface in every state, and 7:1 in high-contrast modes. The indicator and the focus ring have 3:1. The selected tab does not depend on color alone: the indicator is a shape.

Keyboard

Section titled “Keyboard”
Keys Action
ArrowLeft or ArrowRight On the web, moves to the previous or next tab, wrapping at the ends, and selects it unless the activation mode is manual. In right-to-left layouts the keys swap: Left moves to the next tab.
Home or End On the web, moves to the first or last tab, and selects it unless the activation mode is manual.
Enter or Space Selects the focused tab. On the web this is needed only in manual mode; on iOS and Android it is how a keyboard selects.
Tab Moves focus into the list, to the selected tab, and from there to the panel: to its first control, or to the panel itself when it has nothing focusable. On iOS and Android focus moves between tabs as the platform moves it.

Internationalization

Section titled “Internationalization”
Concern Behavior
Right to left The first tab is on the right, the list scrolls from the right, the leading icon sits on the right of the label, and on the web Left and Right swap.
Long text Labels stay on one line and are never truncated. When the tabs do not fit, the list scrolls sideways.
Scripts The tab height leaves room for stacked Vietnamese diacritics at line height 1.4. CJK labels use system fonts.

Motion

Section titled “Motion”
Concern Behavior
Transitions Fill and label color changes, and the indicator appearing under a newly selected tab, use tabs.transition.duration and its easing.
Reduced motion Color changes are immediate.

Guidelines

Section titled “Guidelines”

When to use

Section titled “When to use”

Use tabs to split one view into two to seven panels of related content that people do not need to compare side by side, such as “Details”, “Reviews”, and “Shipping” on a product.

  • For more than seven panels, or for content people compare, use headings on one screen.
  • Do not use tabs to step through a process. Each tab must make sense on its own.
  • Do not use tabs to move between an app’s main sections. That is navigation.
  • Do not put tabs inside tabs.

Writing the labels

Section titled “Writing the labels”
  • Keep each label to one or two words, in sentence case: “Shipping”, “Order history”.
  • Do not repeat the screen’s title in the labels.
  • A label stays on one line and is never truncated. When translated labels do not fit, the row scrolls sideways; it does not wrap or cut a label short.
  • A count can be part of the label, such as “Reviews (12)”, until a badge component exists.

Icons

Section titled “Icons”
  • An icon beside a label is decoration; the label carries the meaning.
  • A tab with only an icon must be given an accessible name that says what its panel holds. Prefer labels: an icon alone is harder to recognise than a word.

Selection

Section titled “Selection”
  • One tab is always selected. Choose the one people need most often as the first.
  • Hide a tab that leads nowhere instead of disabling it. Tabs have no disabled state, because a disabled tab cannot say why it is disabled.
  • On the web, the arrow keys select the tab they reach, and its panel shows at once. If a panel takes long to show, such as one that loads data, use the manual activation mode: the arrow keys then only move focus, and Enter or Space selects.

Panels

Section titled “Panels”
  • Only the selected tab’s panel is shown. On the web, a panel that is not selected is not rendered at all, unless the app keeps it mounted, for example to keep what was typed into a form.
  • Give a panel its own spacing. Tabs set none between the row and the panel.

Do and don’t

Section titled “Do and don’t”
Do Don’t
Use two to seven tabs for related content in one view Use tabs as an app’s main navigation
Keep labels short, and let a long translation scroll Truncate a label, or shorten it to fit
Hide a tab that has nothing to show Disable a tab
Put content people compare on one screen, under headings Split content people compare across tabs
